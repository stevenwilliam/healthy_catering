# Internationalisation — Evermore

**Languages:** Bahasa Indonesia (`id`, default), English (`en`), Simplified
Chinese (`zh`). Added 2026-08-18 on Steven's instruction; `id` and `en` were
already the plan (CLAUDE.md §10), `zh` is new.

---

## 1. Where the strings live

**No literal copy in a template or a component.** Every visible string is a key
in a catalogue, which is what makes a fourth language a data edit rather than a
rewrite.

| Surface | Catalogue | Lookup |
|---|---|---|
| Public pages (Go templates) | `internal/adapter/http/messages.go` | `{{t .L "key"}}` |
| App (React) | `web/src/lib/messages.ts` | `const t = useT()` → `t('key')` |
| Notifications | `internal/adapter/notify/templates.go` | per-locale map on each message |

The mechanism is `internal/platform/i18n`, which is business-agnostic and
portable: locales, negotiation, path prefixes and `Catalog` lookup, and nothing
about catering.

**Fallback is Indonesian, never blank.** A key missing a Chinese string renders
the Indonesian one. A key that does not exist at all renders *itself* — ugly on
purpose, so it surfaces in review rather than shipping as silence.

**The catalogue is enforced.** `TestPublicMessagesComplete` fails if any key
lacks any locale, so a half-translated string cannot land quietly.

## 2. How a locale is chosen

The two surfaces answer this differently, and deliberately.

**Public pages — the URL carries it.**

```
/                 /en/                /zh/
/menu/keto        /en/menu/keto       /zh/menu/keto
```

The default locale keeps the bare paths it has always had, so no existing link,
bookmark or indexed URL breaks. A cookie was rejected: it serves three
different bodies at one address, which breaks sharing a link and hands a search
engine one URL with three contents.

Each page therefore ships `hreflang` alternates for all three plus `x-default`,
and `sitemap.xml` lists every page in every language with `xhtml:link`
alternates on each entry.

**The app — a stored preference.** `/app` is `noindex` and behind a login, so
there is nothing to share or index and the opposite trade is right: the choice
lives in `localStorage` under `evermore.lang`, follows the customer between
screens, and changes no routes. First visit falls back to `navigator.languages`,
matched on the primary subtag so `zh-TW` and `en-GB` still land somewhere sensible.

## 3. The language selector

Same design on both surfaces:

- **Closed, it shows the CURRENT language** — flag plus the language's own name.
  A generic globe icon tells a reader who has landed in the wrong language
  nothing about what they are looking at.
- **Every option is written in its own language** (`Bahasa Indonesia`,
  `English`, `中文`). Someone who cannot read Indonesian must still be able to
  find their way out of it, which a list written in Indonesian prevents.
- **Switching keeps the reader on the same page.** `/zh/menu/keto` → `English`
  lands on `/en/menu/keto`, not on the home page.
- The current entry carries `aria-current` (public) or `aria-checked` (app)
  **and** a tick — never colour alone (99 §8).

Two implementation points that are not arbitrary:

**The flags are inline SVG, never the flag emoji.** Windows ships no glyphs for
regional-indicator pairs, so 🇮🇩 🇬🇧 🇨🇳 render as the letter boxes "ID" "GB"
"CN" on the browser most of this audience uses — in the one control that must
not be ambiguous.

**The flags are `aria-hidden` decoration; the NAME is the label.** A flag is a
country, not a language: English is not the flag of one country, and Chinese is
read in several. The flag is there because Steven asked for it and because it
is a fast visual anchor; it is not what carries the meaning.

The public selector is a `<details>` disclosure with no JavaScript at all — the
CSP has no `'unsafe-inline'` and the marketing pages ship no bundle, and a
disclosure widget is keyboard-operable and announced as expandable for free.

## 4. What is NOT translated

**Catalogue content**: diet-type names and descriptions, meal names, food item
names, and the per-diet SEO overrides. These are database rows with a single
`name`/`description` column, so they render in whatever language they were
entered in, whichever locale is selected. Raised as **docs/03 Q-24** with a
proposed JSONB `translations` column — but the real question there is whether
the food is translated at all, which is Steven's call and an ongoing cost.

**Server-side validation messages**: the API returns already-worded errors, so
a form error still appears in the API's language. Fixing it properly means
error *codes* through `platform/apierror` that the client renders from its own
catalogue. Worth doing; not done.

**Admin-only screens** beyond their navigation labels — see §5.

## 4a. Type: neither brand face covers Chinese

Erode is a Latin display face and the Inter variable file is Latin/Greek/
Cyrillic, so **no Han character is rendered by a brand font**. A Chinese
headline is not set in Erode and cannot be; it falls through the stack.

`web/public/fonts/fonts.css` therefore names a `--font-cjk` list before the
generic fallback — PingFang on Apple, Microsoft YaHei on Windows, Noto on Linux
and Android. Nothing is downloaded: a CJK webfont runs to megabytes and every
platform already ships a good one. Without that list the fallback is the
browser's last-resort serif, which sitting beside the Latin text on the same
page reads as a rendering fault rather than as a second script.

The practical consequence: **the Chinese pages do not carry the brand's display
voice**, only its colour, layout and wordmark. Buying a CJK display face that
pairs with Erode is a brand decision and a licence cost, not an engineering
one.
